# Задача на разработку: Улучшить CLI и получение API-ключа

Добавить параметры `--cwd <path>` и `--api-key <key>`; сделать так, чтобы `cwd` из любого источника мог быть относительным и разрешался относительно рабочего файла конфигурации; разрешить пустой `api-key` в файлах агентов и запрашивать ключ в консоли, если он не задан.

Зачем: нужна единая корневая рабочая директория агентского цикла с предсказуемым приоритетом задания, а также предсказуемый порядок получения API-ключа: CLI → файл агента → консоль.

Ожидаемый результат:
- `harness.exe [--cwd <path>] [--api-key <key>] --prompt "..."` работает с указанными приоритетами.
- Относительный `cwd` из CLI или `harness.json5` разрешается относительно каталога рабочего файла конфигурации.
- В файле агента `"api-key": ""` является валидным; если ключ не задан и не передан через CLI, пользователю предлагается ввести его в консоли.

## Функциональные требования

### 1. Параметр `--cwd <path>`

- Добавить в `crates/harness/src/cli.rs`:
  - поле `cwd: Option<PathBuf>` в вариант `CliAction::Start`;
  - разбор `--cwd <path>` и `--cwd=<path>` с ошибкой при отсутствии значения.
- `--cwd` допустим только для запуска сессии (`--prompt`, `--prompt-file`, `--dump`). При использовании с `--help`, `--help-tools`, `--version`, `--conf-new` — возвращать понятную ошибку.
- `--cwd <path>` имеет наивысший приоритет: если задан, используется вместо `cwd` из `harness.json5` (или из dump).
- Если `cwd` (из CLI или конфигурации) относительный, он разрешается относительно каталога рабочего файла конфигурации:
  - для `--conf <path>` — `parent(<path>)`;
  - для конфигурации по умолчанию `<process-cwd>/harness.json5` — каталог процесса;
  - для `--dump <path>` — каталог, восстановленный из dump как `conf_dir` (на основе `agent.config` из встроенных настроек).
- Итоговый `Settings.cwd` должен быть абсолютным и нормализованным (без `./` и `../`), чтобы остальные части системы работали с каноническим корнем.
- Изменить сигнатуры `conf::load_with` / `conf::load_from_value` (и, при необходимости, `conf::load`) так, чтобы можно было передать `cwd_override: Option<PathBuf>`.
- Обновить `crates/harness/help.txt`: описать `--cwd`, его приоритет и правило разрешения относительного пути.

### 2. Параметр `--api-key <key>`

- Добавить в `CliAction::Start` поле `api_key: Option<String>`.
- Разобрать `--api-key <key>` и `--api-key=<key>`; при пустом значении возвращать ошибку.
- Допустим только для запуска сессии (`--prompt`, `--prompt-file`, `--dump`), как `--cwd`.
- `--api-key <key>` имеет наивысший приоритет относительно всех других источников ключа.
- После загрузки настроек значение `<key>` трактовать так:
  - если `<key>` — путь к существующему файлу (относительный путь разрешается относительно итогового CWD), прочитать файл как UTF-8 и взять обрезанное (`trim`) содержимое;
  - иначе считать `<key>` самим ключом.
- Полученным значением перезаписать `settings.agent.api_key` до создания агента.
- Не записывать фактический ключ в dump и не выводить его в логи.

### 3. Пустой `api-key` в файле агента

- В `crates/conf/src/load.rs::resolve_api_key` разрешить пустую строку `api-key` (в том числе строку из пробелов — трактовать как пустую) и возвращать пустую строку без ошибки.
- Отсутствие ключа `api-key` в файле агента по-прежнему должно быть ошибкой.
- Проверить, что сканирование каталога агентов (`scan_agent_dir`) не читает `api-key` и не отбраковывает файлы с пустым ключом.

### 4. Запрос ключа в консоли

- После загрузки настроек и применения CLI-переопределения проверить `settings.agent.api_key`.
- Если ключ пустой, вывести в stdout запрос вида `Enter API key for <vendor> <name>: ` и прочитать строку из stdin.
- Прочитанное значение обрезать (`trim`); если ввод пустой или stdin закрыт (EOF) — вернуть ошибку запуска `api-key is required`.
- Введённый ключ использовать как литеральный ключ; не сохранять его в файл агента и не записывать в dump.

### 5. Поведение с `--dump`

- `--cwd` и `--api-key` могут использоваться вместе с `--dump`.
- Конфигурация загружается из dump; после этого применяются те же правила переопределения `cwd` и `api-key`, что и для новой сессии.
- Если в dump-настройках `agent.config` отсутствует или некорректен, поведение `conf_dir_of` остаётся прежним.

## Проверка корректности решения

- `cargo check --workspace` и `cargo test --workspace` без ошибок.
- Добавить/обновить юнит-тесты:
  - разбор `--cwd`, `--cwd=...`, `--api-key`, `--api-key=...`;
  - ошибки при использовании с `--help` / `--conf-new`;
  - `resolve_api_key` возвращает пустую строку для пустого `api-key` и ошибку для отсутствующего ключа;
  - резолвинг относительного `cwd` относительно `conf_dir`.
- Ручные проверки:
  - конфигурация с `"cwd": "."` в подкаталоге: запуск из другого каталога с `--conf <sub>/harness.json5` использует подкаталог как CWD;
  - `--cwd <relative>` переопределяет `cwd` конфигурации;
  - `--api-key` с литеральным ключом и с путём к файлу относительно CWD;
  - файл агента с `"api-key": ""` без `--api-key` вызывает консольный запрос; с `--api-key` запрос не появляется.

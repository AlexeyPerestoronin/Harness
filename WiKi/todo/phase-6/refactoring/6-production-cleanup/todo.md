# Задача на рефакторинг: очистка production-кода от тестов и мёртвого кода

## Цель рефакторинга:
Удалить из кодовой базы всё, что не требуется для работы на «боевом посту». Это последняя задача цикла рефакторинга; она выполняется после того, как все функциональные и рефакторинговые изменения проверены. Основные цели — unit-тесты, test-only зависимости и мёртвый код, оставшийся от предыдущих фаз.

## Вносимые изменения:

### Изменение №1: удаление unit-тестов
- **Что хотим изменить и почему это лучше:** production-сборка не должна содержать `#[cfg(test)]`-модули и тестовые функции.
- **Как есть сейчас:** тестовые модули разнесены по всем крейтам (`logger`, `interactions`, `auth`, `harness-api`, `conf`, `tools`, `agent-loop`, `cli-harness`, `web-harness`).
- **Как должно быть:** все `#[cfg(test)]`-модули и `#[cfg(test)]`-атрибуты у тестовых функций удалены. Логика production-кода не изменяется.

### Изменение №2: удаление test-only зависимостей
- **Что хотим изменить и почему это лучше:** манифесты должны содержать только необходимые production-зависимости.
- **Как есть сейчас:**
  - `crates/cli-harness/Cargo.toml` содержит `[dev-dependencies] tower`;
  - `crates/tools/Cargo.toml` содержит `[dev-dependencies] async-trait`.
- **Как должно быть:** dev-dependency секции удалены. Обычные зависимости, которые используются только тестами, также должны быть удалены, если после удаления тестов они стали неиспользуемыми.

### Изменение №3: удаление мёртвого кода в `logger`
- **Что хотим изменить и почему это лучше:** `DoubleLogger` был оставлен только для компиляции старого бинарного крейта `crates/harness`, который уже удалён. `NullLogger` не используется production-кодом workspace.
- **Как есть сейчас:**
  - `crates/logger/src/double.rs` и экспорт `DoubleLogger` существуют;
  - `crates/logger/src/null.rs` и экспорт `NullLogger` существуют.
- **Как должно быть:** `DoubleLogger` и `NullLogger` удалены, если после удаления тестов у них нет production-потребителей. Модульная документация `crates/logger/src/lib.rs` обновлена. Остаётся контракт `Logger` и `FileLogger`.

### Изменение №4: удаление прочего мёртвого/ненужного кода
- **Что хотим изменить и почему это лучше:** не оставлять код, не участвующий в production-сборке.
- **Как есть сейчас:** встречаются устаревшие `#[allow(dead_code)]` и helper'ы, ставшие ненужными после предыдущих задач (например, возможно оставшиеся после удаления `agent_select::choose`).
- **Как должно быть:** удалены неиспользуемые `use`-объявления, helper'ы и obsolete-атрибуты, выявленные компилятором/поиском. Поведение production-кода не меняется.

## Проверка корректности рефакторинга:
1. `cargo build --workspace` — успех, без warnings и без deprecated-кода.
2. `cd crates/web-harness && trunk build --release` — успех.
3. Поиск по `crates` не находит `#[cfg(test)]` и `[dev-dependencies]`.
4. `cargo tree -p cli-harness` и `cargo tree -p tools` не содержат test-only зависимостей.
5. Ручная smoke-проверка серверного режима: `cargo run -p cli-harness -- --serve` — стартовый блок и Bearer-токен выводятся, `GET /health` отвечает.

## Scope
Минимально необходимые изменения:

- `crates/**` — удаление `#[cfg(test)]`-модулей и тестовых функций
- `crates/cli-harness/Cargo.toml`
- `crates/tools/Cargo.toml`
- `crates/logger/src/lib.rs`
- `crates/logger/src/double.rs` (удаление)
- `crates/logger/src/null.rs` (удаление, если не используется)
- прочие `crates/*/Cargo.toml` при обнаружении test-only зависимостей

Справочные материалы для чтения:

- `Cargo.toml`
- `crates/*/Cargo.toml`
- `crates/logger/src/**`
- `crates/cli-harness/src/**`
- `crates/tools/src/**`

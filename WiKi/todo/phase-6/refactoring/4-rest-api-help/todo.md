# Задача на рефакторинг: создание инструкции `REST-API.help.md`

## Цель рефакторинга:
Актуализировать документацию серверного режима: написать полноценную инструкцию по REST API сервера в виде отдельного файла `REST-API.help.md`.

## Вносимые изменения:

### Изменение №1: новый файл `REST-API.help.md`
- **Что хотим изменить и почему это лучше:** сейчас описание API распределено между `WiKi/todo/phase-6/consulting 5/api.md` и кодом обработчиков. Пользователю/интегратору нужен один самодостаточный справочный файл в корне репозитория.
- **Как есть сейчас:** отдельного файла `REST-API.help.md` нет.
- **Как должно быть:** в корне репозитория создан `REST-API.help.md` на английском языке.

### Изменение №2: содержание инструкции
- **Что хотим изменить и почему это лучше:** документ должен покрывать весь реализованный API и позволять работать с сервером без чтения исходного кода.
- **Как есть сейчас:** информация разбросана.
- **Как должно быть:** `REST-API.help.md` содержит:
  1. Общие сведения: base URL, HTTPS, Bearer-аутентификация, формат ошибки `{ "error": { "code", "message" } }`, CORS-правила.
  2. Endpoint `GET /api/v1/health` (открытый): назначение, пример ответа, поля.
  3. Защищённые endpoint'ы жизненного цикла:
     - `POST /api/v1/run` — запрос `{ "prompt": "..." }`, ответы `202`/`400`/`409`/`412`, `runUrl`;
     - `GET /api/v1/run/current` — состояния `idle`/`running`/`waiting_input`/`stopping`/`finished`/`failed`/`stopped`, примеры ответов;
     - `POST /api/v1/run/stop` — идемпотентность, ответы;
     - `POST /api/v1/run/input` — `{ requestId, answer }`, валидация `text`/`confirm`, ошибки `400`/`404`/`409`.
  4. Config API:
     - `GET /api/v1/config`;
     - `PUT /api/v1/config`;
     - `POST /api/v1/config/default`;
     - redaction секретов и merge-правило.
  5. FS API:
     - `GET /api/v1/fs/list?path=<rel>`;
     - `GET /api/v1/fs/read?path=<rel>`;
     - `PUT /api/v1/fs/write?path=<rel>`;
     - `POST /api/v1/fs/mkdir?path=<rel>`;
     - `DELETE /api/v1/fs/remove?path=<rel>`;
     - `POST /api/v1/fs/move?src=<rel>&dst=<rel>`;
     - правила путей, deny-list, redaction/merge.
  6. Polling-сценарий клиента: `POST /run` → `GET {runUrl}` каждые 10 секунд → `pendingInput` → `POST /run/input` → `result`.
  7. Сводная таблица endpoint'ов.
  8. Секция со специальной нотацией: встроенный блок OpenAPI 3.0 (YAML) для всех описанных endpoint'ов (как вариант machine-readable нотации, аналогичной Postman-коллекции), чтобы документ можно было использовать и как человекочитаемый справочник, и как источник для импорта.

## Проверка корректности рефакторинга:
1. Файл `REST-API.help.md` существует в корне репозитория.
2. Файл написан на английском языке, не содержит русскоязычных фрагментов.
3. Все endpoint'ы, перечисленные в документе, соответствуют реальному роутеру в `crates/cli-harness/src/server/handlers.rs` и DTO из `crates/harness-api/src/lib.rs`.
4. Примеры запросов/ответов согласованы с `WiKi/todo/phase-6/consulting 5/api.md` и фактическими обработчиками.
5. OpenAPI-блок синтаксически корректен (допустима ручная проверка).

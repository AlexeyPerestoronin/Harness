# Что необходимо доработать:
## Сведение операций ввода/вывода в единую зону ответственности
1. Изменить интерфейс `Logger` следующим образом:
    Было:
    ```rs
    pub trait Logger: Send + Sync {
        fn log_str(&self, message: &str);
        fn log_line(&self, message: &str);
    }
    ```

    Стало:
    ```rs
    pub trait Logger: Send + Sync {
        fn log_str(&self, message: &str, new_line: bool);
    }
    ```

2. Изменить интерфейс `Interaction` следующим образом:
    ```rs
    enum OutputType {
        ContinueLine, // продолжает запись с текущей позиции
        NewLine, // продолжает запись с новой строки
        RewriteLine // перезаписывает строку
    }

    pub trait Interaction: Send + Sync {
        // запрашивает ввод пользователя
        fn input(&self, write_log: bool);
        // вводить тестовые данные
        fn output(&self, message: &str, write_log: bool, new_line: OutputType);
    }
    ```

3. Для `Logger` должны быть две реализации:
    - `FileLogger` - записывает данные в файл лога
    - `WebLogger` - отправляет данные на Клиент через SSE

4. `Interaction` имеет 2 реализации:
    - `CliInteraction` - при работе harness в режиме командой строки
    - `WebInteraction` - при работе harness в режиме сервера

5. Обе реализации `Interaction` при создании получают список `dyn Logger`, элементы которого используют для логирования ввода/вывода с флагом `write_log`:
    - `CliInteraction` будет иметь в списке только реализацию логирования в файл `FileLogger`
    - `WebInteraction` будет иметь в списке обе реализации `FileLogger` и `WebLogger`, чтобы лог одновременно записывался как на файл, так и отправлялся web-клиенту для отслеживания прогресса, причём `input/output` операции с `write_log=False` тоже отправляются клиенту на сервер, т.к. тоже являются частью прогресса (различные таймеры, или иная служебная информация, не попадающая в лог)

6. Зависимости между крейтами должны получиться такими: ./crate/logger → ./crate/interaction → (все прочие крейты, которым требуются работать с операциями input/output)

Можно критиковать!
Предлагать лучшее решение!

## Отсутствие запущенного harness
В сценарии, когда `harness.exe` не запущен по нужному порту, или вообще отсутствует в системе, ничего не скачивать и не запускать удалённо!
Просто выводить пользователю модальное окно в котором будет инструкция как скачать и запустить `harness.exe`.

Для упрощения процесса для пользователя, он должен будет выполнить всего 2 действия: скачать исполняемый файл и запустить его без параметров.
Запуск `harness.exe` без параметров запускает его в режиме сервера на порту по умолчанию.
Дальнейшая настройка будет происходить из web-интерфейса.

## Ответы на вопросы:
1. **Трактовка варианта B.** Подтвердить, что «полностью асинхронный (axum + sync request)» означает **axum + async reqwest** для вендорных запросов. Если имелся в виду иной смысл — требуется уточнение.

Ответ: подтверждаю, используем полностью асинхронный стек: axum + async request + tokio

2. **Удалённый запуск.** Для сценариев №2 и №3: достаточен ли в первой версии пользовательский bootstrap (сгенерированная команда), или сразу проектируем демон `harness-remote` с автозапуском и скачиванием релиза?

Ответ: этих сценариев больше нет! → используем модальное окно.

3. **Аутентификация.** Обязателен ли bearer-токен для не-loopback сервера в первой версии, или MVP допускает `--host 0.0.0.0` без токена при условии предупреждения?

Ответ: токен не обязателен.

4. **Хранение расшифрованного API-ключа.** Удалять ли расшифрованный ключ сразу после завершения цикла или хранить в памяти до истечения `live-timeout`?

Ответ: сохранять ключ в зашифрованном виде для конкретного вендора до остановки сервера.

5. **Область FS API.** Разрешить UI работу со всем деревом `cwd` или ограничить только `harness.json5` + каталоги `roles`/`skills`/`agents`?

Ответ: разрешить работу со всем деревом.

6. **Третий артефакт.** Подтвердить, что в первой итерации достаточно source-level крейта `web-harness` (без runtime `harness-plugin.wasm`), либо указать, что динамическая загрузка плагина обязательна.

Ответ: на пока загрузка в runtime отменяется, плагин будет загружаться через cargo-крейт.

7. **Платформы сборки.** `harness.exe` собирать только для Windows или также Linux/macOS (учитывая сценарии удалённых машин)?

Ответ: под все машины.

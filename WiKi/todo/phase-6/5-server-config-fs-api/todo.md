# Задача на разработку: Config API и FS API сервера (`/api/v1/config`, `/api/v1/fs/*`)

Добавить в `crates/cli-harness` эндпоинты управления конфигурацией и файловой системой внутри `cwd` с deny-list, redaction секретов и merge-правилом.

Зачем: встраиваемые web-приложения с фичей `fs-panel` должны редактировать `harness.json5` и файлы проекта через защищённое REST API, при этом секреты не должны покидать сервер, а защищённые пути — быть недоступны.

Ожидаемый результат: `GET/PUT /api/v1/config`, `POST /api/v1/config/default` и все `GET/PUT/POST/DELETE /api/v1/fs/*` реализованы по `api.md` §4–§5, включая redaction, merge-правило, deny-list и нормализацию путей.

## Функциональные требования

### 1. Config API

Реализовать в `crates/cli-harness/src/server/` (модуль `config`):

1. `GET /api/v1/config`:
   - файл существует и валиден → `200 { path, exists: true, text, valid: true, validationError: null }`, где `text` — конфигурация с redaction секретов;
   - файл существует, но невалиден → `200 { path, exists: true, text: null, valid: false, validationError: <сообщение разбора> }`;
   - файл отсутствует → `200 { path, exists: false, text: <шаблон по умолчанию с redaction>, valid: false }`.
2. `PUT /api/v1/config`:
   - принять `{ text }`;
   - разобрать текст как JSON5/JSON и провалидировать через `conf` (та же валидация, что и `load_server_config`, включая `server` и запрет `cors-allowed-origins = ["*"]`);
   - невалидный → `400` с телом `{ ok: false, error: { code: "CONFIG_INVALID", message } }`, файл не сохранять;
   - валидный → применить merge-правило для секретов и сохранить; вернуть `200 { ok: true, path, valid: true }`.
3. `POST /api/v1/config/default`:
   - файл отсутствует → создать `harness.json5` из `conf::template_text()`; вернуть `200` с `path`, `exists: true`, `text` (с redaction), `valid: true`;
   - файл существует → идемпотентно вернуть текущую конфигурацию (с redaction).
4. Redaction конфигурации:
   - секретные ключи: `api-key`, `apikey`, `token`, `secret`, `private-key`, `tls-key`;
   - значения этих ключей заменяются на `"***"` в ответах;
   - если конфигурация не разобрана, сырой текст не возвращается.
5. Merge-правило конфигурации:
   - применяется, только если существующий файл успешно разобран как JSON5/JSON;
   - если во входном тексте значение секретного поля равно `"***"` или `"<redacted>"`, сохранить прежнее значение из существующего файла;
   - если существующий файл отсутствует или не разобран, а во входном тексте секретное поле содержит `"***"`/`"<redacted>"` → `400`;
   - новое фактическое значение секретного поля записать можно; обратно оно никогда не возвращается.
6. Если merge-правило не срабатывало, сохранять исходный текст запроса; если срабатывало — сохранять канонический JSON (валидный JSON5) с обновлёнными значениями секретных полей.

### 2. FS API

Реализовать в `crates/cli-harness/src/server/` (модуль `fs_api` или `fs`):

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/fs/list?path=<rel>` | Содержимое каталога |
| `GET` | `/api/v1/fs/read?path=<rel>` | Чтение текстового файла |
| `PUT` | `/api/v1/fs/write?path=<rel>` | Создание/перезапись текстового файла |
| `POST` | `/api/v1/fs/mkdir?path=<rel>` | Создание каталога |
| `DELETE` | `/api/v1/fs/remove?path=<rel>` | Удаление файла/пустого каталога |
| `POST` | `/api/v1/fs/move?src=<rel>&dst=<rel>` | Перемещение/переименование |

Форматы запросов/ответов — по `api.md` §5.

1. Пути:
   - `path`, `src`, `dst` — относительные пути от `cwd`;
   - нормализация пути до обращения к ФС;
   - запрещены абсолютные пути, `..`, symlink/переходы за пределы `cwd` (проверять через нормализацию и `canonicalize`);
   - текстовые файлы читаются/пишутся как UTF-8.
2. Deny-list (проверка после нормализации, до обращения к ФС; ошибка `403 FORBIDDEN_PATH`):
   - `.harness/**`;
   - `harness.json5` (конфигурация только через Config API);
   - каталог логов сессий (`<log-folder>/**`, по умолчанию `.log/**`) — полностью, и для активных, и для завершённых сессий (корректировка H4 Designer-Reviewer);
   - секретоподобные файлы: `.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa`, `id_ed25519`.
3. Redaction на чтении:
   - применяется только к файлам, которые сервер успешно разобрал как JSON5/JSON;
   - секретные ключи — те же, что в Config API; сравнение по точному имени, без substring-поиска;
   - значения заменяются на `"***"`;
   - прочие текстовые файлы (Markdown, YAML, код и т.п.) возвращаются как есть.
4. Merge-правило на записи:
   - применяется только к разобранным JSON5/JSON;
   - `"***"`/`"<redacted>"` для секретного поля → сохранить прежнее значение из существующего файла;
   - если существующий файл не разобран или отсутствует, а в тексте есть `"***"` для секретного поля → `400`;
   - прочие файлы перезаписываются как есть.
5. `GET /api/v1/fs/list` возвращает `entries` с `name`, `kind` (`file`/`dir`), `size` (для файлов). Защищённые deny-list'ом пути не должны быть доступны; сервер возвращает `403` при прямом обращении к ним.
6. Все обработчики защищены Bearer-токеном (роутер уже имеет слой `require_auth`; достаточно добавить маршруты в защищённую группу).

### 3. Интеграция с `ServerState`

1. Использовать существующий `ServerState`/`LoadedServerConfig` для получения `cwd`, `log-folder`, `config_state`.
2. Мутирующие вызовы (`PUT /config`, `POST /config/default`, `PUT /fs/write`, `POST /fs/mkdir`, `DELETE /fs/remove`, `POST /fs/move`) сбрасывают `live-timeout` через общий хелпер, добавлённый в серверной части.
3. `GET /config` и `GET /fs/*` не продлевают `live-timeout`.

## Проверка корректности решения

1. `cargo build --workspace` и `cargo test -p cli-harness` — успех.
2. Юнит-тесты:
   - нормализация путей: `..`, absolute path, symlink-выход за `cwd`;
   - deny-list: `.harness/**`, `harness.json5`, каталог логов, `.env`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa`, `id_ed25519` недоступны для чтения/записи/удаления;
   - redaction: чтение файла агента не содержит `api-key`; `GET /config` не содержит `tls-key`; произвольный текстовый файл не подвергается substring-редкации;
   - merge: `PUT` с `"***"` сохраняет старое значение для разобранных JSON5/JSON; создание нового файла с `"***"` → `400`;
   - Config API: `missing`/`invalid`/`ok`; `PUT` невалидной конфигурации не сохраняет файл; `POST /config/default` идемпотентен.
3. Ручная проверка локального сервера:
   - `curl -k -H "Authorization: Bearer <token>" "https://localhost:4067/api/v1/fs/list?path=roles"`;
   - чтение файла агента возвращает `"api-key": "***"`;
   - попытка чтения `harness.json5` через FS → `403 FORBIDDEN_PATH`;
   - `GET /config` и `PUT /config` по сценариям `api.md` §4.

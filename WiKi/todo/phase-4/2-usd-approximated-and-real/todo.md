# Задача на разработку: Аппроксимированная и реальная стоимость в логе цикла
В цикле агента всегда считать аппроксимацию USD по ценам модели и отдельно показывать реальную стоимость, если её прислал ответ API. Жёстко заданные прайсы в коде вендоров удалить.

Зачем: одна и та же модель не должна стоить по таблице в json5 и по другой таблице в `deepseek.rs` / `alibaba.rs`. В логе должно быть видно оба числа, а не одно безымянное `usd`.

Ожидаемый результат: заголовок итерации в `log.md` и на консоли выглядит так:

```md
## Iteration №5
Usage:
- tokens = 100000
- USD approximated = 10.34
- USD real = 10.45
```

Если ни один ответ сессии не содержал стоимость:

```md
- USD real = doesn't obtained from response
```

Строка `doesn't obtained from response` — буквально такая, с этой грамматикой. Не исправлять на «wasn't».

## Функциональные требования
### 1. Откуда берутся цены
1. Цены уже лежат на `AgentSettings`: `input_price`, `output_price`, `cached_price` (`f64`, `-1` = бесплатно). Не читать json5 из агента и не парсить файл модели второй раз. Crate `conf` и `harness/agents/*.json5` не менять. Если этих полей нет — остановись и спроси, не заводи свою схему.
2. Удалить `prices_for` в `deepseek.rs` и `alibaba.rs` и любые другие зашитые USD/1M. `OpenAiCompatAgent` получает цены из `AgentSettings`, не от обёртки вендора.
3. Проверку «в файле нет price» не дублировать. Её делает загрузчик до `AgentLoop::new`. Здесь цен уже нет только если загрузчик сломан.

### 2. Аппроксимация
Считать на каждом успешном ответе и копить в том поле, которое сегодня называется `UsageStats.total_cost_usd`. Это поле становится аппроксимацией. Имя поля не переименовывать: старые dump должны открываться. Комментарий к полю обновить.

Формула одной ответа (та же, что уже в `usd_cost`, плюс правило `-1`):

```text
input_price  = 0 если input_price  < 0 иначе input_price
output_price = 0 если output_price < 0 иначе output_price
cached_price = 0 если cached_price < 0 иначе cached_price
uncached     = max(input_tokens - cached_tokens, 0)
usd          = uncached / 1_000_000 * input_price
             + cached_tokens / 1_000_000 * cached_price
             + output_tokens / 1_000_000 * output_price
```

`input_tokens` в этой формуле — все входные токены ответа, включая кэш. `cached_tokens` — подмножество input (cache hit / cache read). Кэш не тарифицируется второй раз по input.

Проверка: input=1_000_000, cached=200_000, output=500_000, цены 2 / 10 / 0.1 → `6.62`. Те же токены и `cached-price = -1` → `6.60`. Все три цены `-1` → `0`.

Один помощник на всех вендоров (можно перенести нынешний `usd_cost` в `agents/mod.rs`). Не копировать формулу в пять файлов.

Какие счётчики класть в формулу:

- xAI, DeepSeek, AliBaba, Google — как сейчас: input уже включает cached, cached лежит отдельно. Формула с вычитанием верна. Не «чинить» Google, складывая cached поверх `promptTokenCount`.
- Claude сейчас cached не читает, а `usage.input_tokens` **не включает** cache read/creation. Иначе кэш уйдёт в input-цену или пропадёт. Записать:
  - `cached_tokens = usage.cache_read_input_tokens` (нет поля → 0);
  - `input_tokens = usage.input_tokens + cache_read_input_tokens + cache_creation_input_tokens` (нет полей → только `input_tokens`).
  Cache creation отдельной цены не имеет — он остаётся во входе и тарифицируется как input. Четвёртую цену не выдумывать.
- Если форма ответа Клода не такая — остановись и спроси, не подбирай другие имена полей.

`Agent::consumed_usd()` возвращает эту накопленную аппроксимацию. Проверка `USD-limit` в цикле по-прежнему сравнивает `consumed_usd()` с сессионным лимитом (до вызова модели, safe/auto-accept не трогать). Реальная стоимость лимит не кормит: её может не быть.

Для xAI это смена смысла: раньше в `total_cost_usd` копилась стоимость из ответа. Теперь туда пишется только аппроксимация. Ответную стоимость класть в отдельное поле (п. 3).

### 3. Реальная стоимость
Реальная стоимость не вычисляется из токенов. Её нет, пока какой-нибудь ответ не прислал явное поле.

Добавить в `UsageStats` поле `real_cost_usd: Option<f64>` с `#[serde(default)]`, чтобы старый dump без поля открывался как `None`, а не падал.

На `Agent` добавить метод (имя зафиксировано):

```rust
/// Vendor-reported USD so far. None if no response had a cost field.
fn consumed_usd_real(&self) -> Option<f64>;
```

Разбор тела ответа, один приоритет для всех вендоров (первое найденное; смотреть объект `usage`, если он есть, и корень; число или числовая строка):

1. `cost_in_usd_ticks` — целое, USD = ticks / 10_000_000_000. Это сумма **этого** запроса: прибавить.
2. Иначе `cost_in_usd`, `cost_usd`, `cost` — сумма этого запроса: прибавить.
3. Иначе `total_cost_usd`, `total_cost` — вендор прислал уже накопительный итог: **заменить** накопленное real этим значением, не прибавлять.
4. Иначе этот ответ стоимость не содержал: `None` не затирать нулём, предыдущий `Some` не сбрасывать.

`Some(0.0)` — вендор прислал ноль. Это не строка `doesn't obtained from response`. Строка только при `None` (ни один ответ сессии не содержал поле).

Не читать стоимость из HTTP-заголовков. Не добавлять новые ключи «на всякий случай». У xAI нынешний `parse_cost_usd` как раз возвращает `0.0`, если полей нет — это надо перестать делать: отсутствие поля и ноль различаются.

### 4. Лог
Заменить текущую строку цикла

```text
## Iteration №{n}: (tokens = {}; usd = {})
```

на блок ниже. Место то же: начало итерации, до вызова модели. Числа — накопительные итоги предыдущих ответов (как сегодняшний `consumed_tokens()` / `consumed_usd()`). На итерации 1 токены и аппроксимация — 0, real — строка отсутствия. Это не баг.

```text
## Iteration №{n}
Usage:
- tokens = {consumed_tokens}
- USD approximated = {number}
- USD real = {number или doesn't obtained from response}
```

`tokens` — существующий `consumed_tokens()`, формулу токенов по вендорам не менять.

Числа USD: без экспоненты; минимум 2 знака после запятой, если значение по модулю `>= 0.01` или равно 0 (`10.34`, `0.00`); если `0 < |usd| < 0.01` — до 6 знаков без хвостовых нулей, чтобы `0.00015` не схлопнулось в `0.00`.

В `finish()` у каждого вендора убрать единственную строку `- total cost: $...` (у Google её нет — добавить учёт). Вместо неё две строки с теми же подписями:

```text
- USD approximated: {number}
- USD real: {number или doesn't obtained from response}
```

Текст `doesn't obtained from response` — одна `pub(crate)` константа, и цикл, и `finish()` берут её оттуда.

Остальной лог итерации (prompt, content, tools, заголовок сессии, лимиты) не переставлять.

### 5. Dump
`real_cost_usd` пишется и читается вместе с остальной статистикой. Старый dump без этого поля загружается, real = не получена, аппроксимация = прежний `total_cost_usd`. Протокол сообщений, URL, заголовки и формат tool call не менять.

## Проверка корректности решения
1. `cargo test --workspace`. Живые API не вызывать.
2. Юнит-тест формулы: пример `6.62` / `6.60` / `0` из п. 2; отрицательная цена даёт 0 вклада.
3. Юнит-тест разбора real без сети:
   - `cost_in_usd_ticks: 10000000000` → `1.0`, это прибавка;
   - нет ни одного ключа → `None`, в лог попала бы строка `doesn't obtained from response`, а не `0`;
   - явный `cost_usd: 0` → `Some(0.0)`;
   - два ответа с per-request `cost_usd` 1.5 и 0.5 → `Some(2.0)`;
   - второй ответ только с `total_cost: 1.25` → накопленное real становится `1.25`, не суммой.
4. Тест формата заголовка на подменённом логере или чистой функции сборки строк: есть `## Iteration №5`, `Usage:`, три буллета, нет старого `(tokens = ...; usd = ...)`.
5. Парсеры ответов Google / xAI / Claude / DeepSeek, которые уже есть, остаются зелёными. Если тестов нет — не ломать разбор текста и tool call; новые тесты гонять на фикстурах JSON, не на HTTP.

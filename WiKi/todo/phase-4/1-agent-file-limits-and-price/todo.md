# Задача на разработку: Новый формат файла агента (`limits` + `price`)
Перевести каждый файл в `harness/agents/*.json5` на новый формат и научить crate `conf` только ему. Старый плоский формат не читать и не мигрировать молча.

Зачем: лимиты модели должны жить одним блоком, цена модели должна быть в файле (а не в коде), `iteration-limit` сессии не должен дублироваться в файле модели.

Ожидаемый результат: файл агента такого вида успешно загружается, старые корневые ключи дают ошибку загрузки, цикл ещё не стартует, если нет `price` или `limits`. HTTP-агенты, текст лога и меню выбора в этой задаче не меняются.

```json5
{
    "vendor": "AliBaba",
    "name": "Qwen-Turbo",
    // api-key or path to file with api-key
    "api-key": "api-key or path to file with api-key",
    "limits": {
        "tokens": -1,
        "USD": -1,
        "rpm": 1500,
        "tpm": 1000000,
        "rpd": -1,
    },
    "price": {
        "input-price": 0.05,   // USD за 1_000_000 входных токенов
        "output-price": 0.20,  // USD за 1_000_000 выходных токенов
        "cached-price": -1,    // -1 = бесплатно
    },
}
```

## Функциональные требования
### 1. Файл модели
1. Обязательные корневые ключи: `vendor`, `name`, `api-key`, `limits`, `price`. Имена — константы в `crates/conf/src/str/keys.rs`, не строковые литералы в загрузчике.
2. `limits` — объект. Обязательные ключи внутри, других ключей нет:
   - `tokens` — целое, `-1` или `>= 1`;
   - `USD` — число, `-1` или `>= 0`;
   - `rpm`, `tpm`, `rpd` — целые, `-1` или `>= 1` (правило сегодняшнего `required_model_int`, тексты ошибок сохранить).
3. `price` — объект. Обязательные ключи, других нет: `input-price`, `output-price`, `cached-price`. Каждый — число, `-1` или `>= 0`. `-1` значит бесплатно, это не ошибка. `0` допустим. Дробное между `-1` и `0`, значение `< -1`, строка, отсутствие ключа — ошибка.
4. Корневые ключи старого формата запрещены, даже если рядом уже есть `limits` и `price`. Не интерпретировать их. Достаточно сообщить про первый найденный:
   - `token-limit`, `iteration-limit`, `iterations`, `USD-limit`, `rpm`, `tpm`, `rpd`.
5. Тексты ошибок — английские, в стиле существующих `ConfError`:
   - нет объекта: `please define 'limits' in the model conf file` / `please define 'price' in the model conf file`;
   - нет вложенного ключа: `please define 'tokens' in the model conf file` (то же для `USD`, `rpm`, `tpm`, `rpd`, `input-price`, `output-price`, `cached-price`);
   - плохое целое лимита: `'rpm' must be -1 or a positive integer` (то же для `tokens`, `tpm`, `rpd`);
   - плохой `USD`: `'USD' must be -1 or a non-negative number`;
   - плохая цена: `'input-price' must be -1 or a non-negative number` (то же для двух других);
   - старый ключ: `'iteration-limit' is not allowed in the model file` (подставить фактическое имя ключа).
6. `vars` по-прежнему подставляются до разбора json5. `api-key` резолвится как сейчас (литерал или файл). Неизвестный агент (`vendor` + `name`) — как сейчас.
7. Обратной совместимости нет: загрузчик не имеет ветки «если ключи плоские — прочитать по-старому».

### 2. Что эти поля значат для сессии
Смысл сессии не менять.

1. При загрузке через `harness.json5` (`load` / `load_with` / `load_from_value`) сессионные `agent.token-limit`, `agent.iteration-limit`, `agent.USD-limit` по-прежнему берутся только оттуда и пишутся в `AgentSettings.token_limit` / `iteration_limit` / `usd_limit`. Поля `limits.tokens` и `limits.USD` файла модели при этом **не подменяют** сессионные лимиты и **не добавляют** второй порог в цикл. Их надо провалидировать и использовать для сканирования (п. 4). Не удалять их из файла.
2. `limits.rpm` / `limits.tpm` / `limits.rpd` по-прежнему попадают в `AgentSettings.rpm` / `tpm` / `rpd`. Имена полей структуры не переименовывать: их читает `VendorRequest`.
3. `load_model` (нет `harness.json5`): `token_limit = limits.tokens`, `usd_limit = limits.USD`, `iteration_limit = -1` (в файле модели итераций больше нет), `rpm`/`tpm`/`rpd` и цены — из файла.
4. На `AgentSettings` добавить три поля и заполнять их всегда, когда файл принят:
   - `input_price: f64`
   - `output_price: f64`
   - `cached_price: f64`
   Значение `-1` сохранять как `-1`, не превращать в `0` на этом слое.
5. Шаблон `crates/conf/settings-template.json5` и ключи сессии `harness.json5` не менять. Комментарий «session token limit is not taken from the model file» остаётся верным.

### 4. Сканирование каталога
`scan_agent_dir` по-прежнему не читает `api-key` и не ходит в сеть. Для каждого кандидата дополнительно прочитать поля, без которых нельзя показать модель:

- `AgentCandidate.token_limit` ← `limits.tokens`
- `AgentCandidate.rpm` / `tpm` / `rpd`
- `AgentCandidate.input_price` / `output_price` / `cached_price`

Если `limits` или `price` нет, значение невалидно, или на корне есть запрещённый старый ключ — файл не кандидат, одна строка `skipped '<file>': <reason>` (как сейчас для прочих битых файлов). Валидные соседи по каталогу остаются в списке. Полная проверка выбранного файла (включая `api-key` и `limits.USD`) по-прежнему в `settings_from_model`: ошибка там происходит до создания сессии и до HTTP.

Сортировка по имени файла и отсев неизвестных `vendor`/`name` не меняются.

### 5. Документация
`README.md` и `README.ru.md`, секция файла модели: вместо плоских `rpm`/`tpm`/`rpd` описать `limits` и `price`. Упомянуть: `-1` в цене = бесплатно; отсутствие `price`/`limits` — ошибка до цикла; `iteration-limit` в файле модели больше нет, итерации сессии задаёт только `harness.json5`. Список известных агентов не менять. Секцию `harness.json5` не переписывать, кроме одной фразы, если она станет ложной.

# Задача
Необходимо сформировать dev-задачи для III фазы разработки:
    - каждая задача должна быть сформулирована в `WiKi/todo/phase-3/<number>-<task-name>/todo.md`
      - шаблон для dev-задачи смотри в `WiKi/harness/templates/development.md`
    - для каждой задаче необходимо сформировать отдельный `harness.json5` в папке с `todo.md`
      - целевой агент я выберу самостоятельно, поэтому достаточно грамотно сформулировать tools и их ограничения.

## Задачи для III фазы:
### Autodetect settings from dump-file
Необходимо добавить в dump-файл, который создаётся в процессе исполнения harness-цикла полную копию конфигурационного файла `harness.json5`, чтобы в случае прерывания продолжить без необходимости в отдельном файле конфигурации:
```json5
{
  "settings" : {
    // вот здесь должна быть копия целевого harness.json5
  },
  "messages": [...]
}
```
Важные моменты:
- при продолжении работы с dump-файла попытка установить конфигурацию через --conf должна приводить к ошибке

### Remove paths
Необходимо удалить секцию `paths` из файла конфигурации `harness.json5`:
```json5
{
    "vars": {...},
    "cwd": "...",
    // надо удалить
    "paths": {...},
}
```
Ключ `"log-folder"` перенести внутрь `"agent-setting"`.
Также необходимо переименовать `"agent-setting"` в просто `"agent"`.

### Agent's skills and roles
Необходимо добавить секции `skills` и `roles` в файл конфигурации `harness.json5`:
```json5
{
    "vars": {...},
    "cwd": "...",
    "paths": {...},
    "agent-setting": {...},
    "tools": {
        "skills": {
            "python-programmer": {
                "description": "Применяется при программировании на Python",
                "file": "<some-path>/harness/skills/python-programmer.md",
            },
            "rust-programmer": {
                "description": "Применяется при программировании на Rust",
                "file": "<some-path>/harness/skills/rust-programmer.md",
            },
            // прочие способности
        },
        "roles": {
            "senior-developer": {
                "description": "Роль 'старший-разработчик' применяется тогда, когда необходимо работать с кодовой базой проекта с целью её изменения.",
                "file": "<some-path>/harness/roles/project-owner.md",
            },
            "project-analyst": {
                "description": "Роль 'аналитик проекта' применяется тогда, когда необходимо работать с кодовой базой проекта с целью её изучения для задач планирования.",
                "file": "<some-path>/harness/roles/project-owner.md",
            },
            // прочие роли
        }
    },
}
```
Важные моменты:
- за навыки и роли, должен быть ответственен отдельный tool-модуль:
  - `./crates/tools/src/skills.rs` - за навыки
  - `./crates/tools/src/roles.rs` - за роли
- агент может запросить подробное описание навыка/умения воспользовавшись tool-командой `get_<skill|role>_explanation(<skill|role>_name: string parameter)` в ответ за что, ему отправляется содержимое соответствующего файла (ключ `"file"`).
- проверка наличия файлов навыков и ролей должна осуществляться до начала цикла и, в случае отсутствия ошибка: `error → <role|skill>-file '<file path>' doesn't find`

### Для всех провайдоров добавить RPM, TPM и RPD с циклом повторов
На текущий момент параметр RPM, TPM и RPD учитываются только для моделей линейки Gemini.
Необходимо сделать так, чтобы указанные параметры фигурировали в настройках всех используемых моделей (см. `./agents`), но в ситуации, когда соответствующий параметр не учитывается в настройках стояло значение `-1`.

Для достижения согласованного логики учёта параметров, контролирующих количество запросов на сервер необходимо создать отдельный модуль `crates\harness\src\vendor_request.rs` в котором реализовать общую логику запросов используя возможности `reqwest-middleware` для разделения кода проверок друг от друга (возможно использование другого крейта, но необходим обосновать чем он лучше).

### Добавить поддержку --prompt-file
Необходимо добавить возможность задавать стартовый промпт через файл: `harness.exe --prompt-file <path_to_prompt>`
В этом случае, по факту должна вызывать команда --prompt, только содержимое должно копироваться из указанного файла.

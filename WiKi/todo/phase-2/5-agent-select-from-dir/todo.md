# Задача на разработку: Выбор агента из папки (`agent-setting.config` может указывать на каталог)
Расширить параметр `agent-setting.config` файла настроек цикла: кроме пути к файлу агента, он может быть путём к **папке** с несколькими файлами конфигураций агентов. В этом случае при запуске пользователю показывается список найденных агентов и предлагается выбрать одного.

Зачем: держать в одной папке настройки нескольких моделей (`agents/`) и выбирать модель при каждом запуске, не правя `harness.json5`. Выбор нужен и при запуске с `--dump`: сессию можно продолжить другим агентом (см. задачу 6).

Предусловие: выполнена задача 1 (`vars`): файлы агентов могут содержать `vars`, поэтому сканирование использует тот же путь чтения, что и загрузка.

Ожидаемый результат:
```
Available agents in C:/MyLife/Harness/agents:
  1) Claude Claude Sonnet 5.5   (claude-sonnet-5-5.json5)
  2) GoogleAI Gemini 3.8 Flash  (gemini-3.8-flash.json5)
  3) SpaceXAI Grok 4.6          (grok-4.6.json5)
Select agent [1-3]:
```
После ввода номера цикл стартует с выбранным агентом, как будто в `config` указан его файл.

## Функциональные требования
### 1. Определение режима
1. Путь `config` разворачивается как сейчас (относительный — от каталога файла `harness.json5`).
2. Если путь — **файл**: поведение не меняется, вопросов пользователю нет.
3. Если путь — **каталог**: режим выбора (п. 2–4).
4. Путь не существует: ошибка как сейчас (`cannot read model file ...`), но если путь без расширения и не существует, сообщение должно подсказывать, что допускается файл или каталог.

### 2. Поиск файлов агентов
1. Сканируется **только корень** каталога (без рекурсии), только файлы с расширением `.json5` (регистронезависимо).
2. Файл считается файлом агента, если он читается через тот же конвейер, что и обычный файл агента (подстановка `vars` → json5), является объектом и содержит строковые `vendor` и `name`, пара которых известна загрузчику (`agent_kind`: поддерживаемые модели).
3. Остальные `.json5` (другой формат, неизвестная модель, ошибка разбора) в список не попадают; на консоль (stderr) выводится одна строка на файл: `skipped '<file>': <reason>`.
4. На этапе сканирования **не** читается и не проверяется `api-key` и не проверяются лимиты/`rpm`: полная валидация выполняется только для выбранного файла (существующий путь `settings_from_model`). Ключи невыбранных агентов не раскрываются и не читаются с диска.
5. Список отсортирован по имени файла (без учёта регистра), нумерация с 1.
6. Пустой список → ошибка `no agent config files found in '<dir>'` (с перечнем пропущенных файлов, если были).

### 3. Выбор пользователем
1. Формат вывода — как в примере выше: `<vendor> <name>` и в скобках имя файла. Приглашение `Select agent [1-N]: `.
2. Ввод: номер из списка. Некорректный ввод (не число, вне диапазона) — повторный запрос, не более 3 попыток, затем ошибка `agent was not selected`. Пустой ввод/EOF на stdin → та же ошибка.
3. Если найден **ровно один** агент — спрашивать не нужно: выбрать его автоматически и вывести строку `Agent: <vendor> <name> (<file>)`.
4. Выбранный агент записывается в лог сессии так же, как сейчас (`- agent: <vendor> <model>` в `log.md`); дополнительно в лог добавить строку `- agent config: <абсолютный путь файла>`.
5. Каталог сессии (`<log-folder>/<YYYY-MM-DD HH-MM>_<vendor>_<model>/`) формируется **по выбранному** агенту, поэтому выбор происходит до `session_dir`.

### 4. Архитектура
1. crate `conf` **не работает со stdin/stdout**: он предоставляет сканирование каталога (список кандидатов: файл, vendor, name) и загрузку настроек по выбранному файлу. Интерактивный выбор — в crate `harness` (новый модуль, например `crates/harness/src/agent_select.rs`).
2. Публичный API `conf` проектируется так, чтобы старый сценарий «config = файл» оставался одним вызовом без выбора, а сценарий «config = каталог» требовал выбора кандидата. Допустимые варианты: `conf::load_with(conf_path, chooser)` с `chooser: &mut dyn FnMut(&[AgentCandidate]) -> Result<usize, String>` либо двухэтапная загрузка. Выбери вариант с минимальными изменениями вызывающего кода (`main.rs`) и обоснуй в `result.md`.
3. Остальные параметры `agent-setting` (`mode`, `token-limit`, `iteration-limit`, `USD-limit`) читаются из `harness.json5` для любого агента, как сейчас.
4. Выбор должен работать и для `--prompt`, и для `--dump` (в `--dump` выбор агента не привязан к тому, кто писал dump).
5. Обновить комментарий к `config` в `crates/conf/settings-template.json5`: «path to an agent file **or to a folder with agent files** (you will be asked to choose)».

## Scope
- `crates/conf/src/load.rs`
- `crates/conf/src/types.rs` (тип `AgentCandidate`)
- `crates/conf/src/lib.rs` (экспорт + тесты)
- `crates/conf/src/<новый модуль сканирования>.rs` — по необходимости
- `crates/conf/settings-template.json5` (только комментарий к `config`)
- `crates/harness/src/main.rs`
- `crates/harness/src/agent_select.rs` (создать)
- `crates/harness/help.txt` — одна фраза в описании `--conf`, что `config` может быть каталогом (если описание `--conf` это затрагивает)

Не менять агентов (`agents/*.rs`), `agent_loop.rs` (кроме строки лога из п. 3.4, если она там формируется) и формат dump.

## Проверка корректности решения
1. `cargo test --workspace`.
2. Unit-тесты в `conf` (tmp-каталоги с файлами, без сети и без реальных ключей):
   - каталог с 3 валидными файлами + 1 нерелевантный `.json5` + `.txt` → 3 кандидата, отсортированы;
   - файл с `vars`, где `vendor`/`name` заданы через переменные → распознаётся;
   - `api-key` невалиден/отсутствует у невыбранного → не влияет на список;
   - пустой каталог → ошибка; рекурсия не выполняется (файл во вложенной папке не найден);
   - `config` = файл → прежнее поведение (все существующие тесты зелёные).
3. Unit-тесты в `harness` для функции выбора с подменой ввода/вывода (`BufRead`/`Write`): корректный номер, повтор при мусоре, 3 неудачи → ошибка, EOF → ошибка, один кандидат → без вопроса.
4. Ручной шаг: `config: "../../../harness/agents"` (папка `WiKi/harness/agents`), запуск `harness.exe --conf <path> --prompt "ping"` — должен показать список и запросить номер. Сеть и реальные ключи не использовать — можно прервать после выбора.

## Задачи для второй фазы:
1. Добавить `deprecated-<dirs|files>` в `harness.json5["tools"]["fs"]`:
    - Конфигурация для инструментария `fs` должна расшириться параметрами `deprecated-<dirs|files>`:
        ```json5
        {
            "tools": {
                "fs": {
                    "available-dirs": [],
                    "available-file-extensions": [],
                    "extra-scope": [],
                    // новый параметр
                    "deprecated-dirs": [
                        "<path to deprecated dir-1>",
                        "<path to deprecated dir-2>",
                    ],
                    // новый параметр
                    "deprecated-files": [
                        "<path to deprecated file-1>",
                        "<path to deprecated file-2>",
                    ],
                },
            }
        }
        ```
    - данные параметры предназначены для перечисления директорий и файлов, которые не должны участвовать в операциях с файловой системой (поиск, создание, удаление, и т.д.)
      - предполагается перечислять временные файлы, файлы логов, директории для сборки и т.д., т.е. всё то, что не должно быть контекстом для анализа
    - данные параметры обязательны для наличия, но могут оставаться пустыми
    - если есть пересечение параметров между `available-dirs` и `deprecated-dirs`, а также между `available-files` и `deprecated-files` программа должна прерываться с подробным сообщением об ошибке:
      - `available-files` на текущий момент записывается как `extra-scope` → надо переименовать.

2. Добавить возможность создавать переменные в файлах конфигурации:
    - В файла конфигурации настройки цикла (например `harness.json5`) и настройках для агента (например `grok-4.6.json5`) необходимо поддержать возможность использовать переменные:
        - в файле для переменных отводится НЕ обязательная специальная секция `vars`, где записываются переменные и их значения:
            ```json5
            {
                "vars" : {
                    "var-name-1": "var-value-1",
                    "var-name-2": "var-value-2",
                }
            }
            ```
        - использование переменной допускается в любой другой части json5-файла в строке отвечающей за некоторое значение через специальный синтаксис `${vars:<var-name>}`:
            ```json5
            {
                "vars": {
                    "test-var-1": "some substitution",
                    "test-var-2": 3.14, // digit value
                },
                "key-1": "${vars:test-var-1} will be placed here",
                "key-2": ${vars:test-var-2}
            }
            ```
        - использование переменных - это просто процесс подстановки значения по ключу:
          - до осуществления всех необходимых подстановок, синтаксис json5 может выглядеть как неправильный, поэтому сначала необходимо осуществить все необходимые подстановки а потом уже парсинг файла
        - логику подстановок надо реализовать в виде отдельного модуля `crates/conf/src/vars.rs`

3. Шаблон файла конфигурации в отдельный файл:
    - Код формирования шаблона конфигурации (см. `crates/conf/src/template.rs` функция `template_text`) необходимо изолировать от текстового шаблона:
      - тестовый шаблон необходимо брать из файла `crates/conf/settings-template.json5`
    - Имеет смыл сформировать шаблон с использованием переменных (`vars`) таким образом, чтобы пользователю для окончательной настройки шаблона было необходимо изменять только эти переменные

4. Модифицировать логику выбора агентов для loop (параметр в файле конфигурации `<settings>.json5[agent-setting][config]`):
    - Случай №1 (как сейчас): в параметре записан путь до конфигурационного файла с агентом для сессии
    - Случай №2 (надо реализовать): в параметре записан путь до папки в которой может быть множество конфигураций для агентов → необходимо просканировать файлы в корне папки и найти файлы, которые являются агентскими файлами конфигурации → дать пользователю выбрать → вывести на консоль список из доступных агентов и спросить пользователя какой использовать.
    Важный момент: необходимо проанализировать логику сохранения dump файла сессии и, если возможно, сделать так, чтобы продолжение с dump файла после прерывания не зависело от целевого агента. Т.е. предполагается наличие возможности продолжить некоторую работу через, например, grok-4,5, тогда как изначальным агентом был выбран claude-sonnet-5.5.

5. Добавить help-user.txt + (--help-tools) + help-ai.txt:
    - необходимо добавить файл `crates/tools/help-user.txt` в котором будут описаны все доступные tools для harness с описанием параметров для настройки:
      - данный файл должен добавляться в код программы при сборке и быть доступным в через новую CLI команду `--help-tool` (подобно тому, как это сейчас работает для `--help` и файла `crates/harness/help.txt`):
    - также необходимо добавить новый tool `crates/tools/src/help.rs`, который будет предоставлять развёрнутую справку по использованию доступных команд из всех имеющихся tools для AI:
      - справка должна из файла `crates/tools/help-ai.txt` где должно быть представлено описание доступных инструментов: имя, параметры, возможные ответы, 2-3 примера использования, возможно что-то ещё (`help-ai.txt` должен линковаться в код программы, подобно тому, как это происходит для `crates/harness/help.txt`)

## 2. Принципы декомпозиции

Задачи сгруппированы по владельцам изменений (крейтам/областям), чтобы:

1. **Не пересекались write-scope.** Ни одна пара задач не пишет в один и тот
   же файл. Задача 8 дополнительно пишет только сигнатуру
   `crates/agent-loop/src/agent_loop.rs` (контракт `AgentLoop::new`), тогда
   как задача 9 пишет в остальные файлы `agent-loop` (`agents/*`,
   `vendor_request.rs`, `dump_settings.rs`) — пересечений нет.
2. **Задачи были независимы на уровне формулировок.** В текстах задач нет
   ссылок «выполнять после задачи N»; каждая задача самодостаточна и
   проверяется локально (`cargo test -p <crate>` /
   `cargo clippy -p <crate>`).
3. **Сложность — средне-высокая.** Документация вынесена в отдельную
   целостную задачу (4 файла, много точечных правок); каждая кодовая задача
   покрывает связный набор изменений в одном крейте/домене.

Сознательно **не разносились** по отдельным мелким задачам clippy-фиксы:
они сгруппированы с доменными изменениями соответствующего крейта, чтобы
не плодить задачи низкого уровня сложности.

## 5. Предполагаемая последовательность исполнения

Задачи 5–9 **независимы и могут выполняться параллельно** (разные файлы,
разные крейты). Рекомендуемый порядок сдачи:

1. **Задачи 5–9 параллельно.** Каждая закрывает свою область и проверяется
   локально (`cargo test -p <crate>` / `cargo clippy -p <crate>`).
2. **Задача 10 последней.** Она включает clippy-гейт `-D warnings` в CI.
   Её следует брать только после того, как задачи 6–9 закрыли все
   clippy-предупреждения, иначе CI станет красным.
3. После сдачи всех задач выполнить сквозную проверку
   `cargo check --workspace`, `cargo test --workspace`,
   `cargo clippy --workspace --all-targets -- -D warnings`.

Такая последовательность сохраняет параллельность основной массы работы и
гарантирует, что CI-гейт вводится на уже чистой кодовой базе.

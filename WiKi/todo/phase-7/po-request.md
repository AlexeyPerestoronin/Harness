# Задачи для 7 фазы разработки:

Основная цель 7 фазы разработки - доработать серверную часть приложения.

## CWD first
Необходимо улучшить/исправить логику работы CWD:
1. CWD исключается из параметров агентского конфигурационного файла `harness.json`
2. CWD задаётся либо явно через `--cwd` при запуске из консоли либо по умолчанию получает CWD процесса.
3. CWD при запуске до начала цикла выводится в консоль с целью информирования
4. Все относительные пути, которые задаются в harness.json вычисляются относительно CWD и не могут выходит за его пределы во вне.
5. Если при запуске файл конфигурации задаётся явно через `--conf <conf>.json5` то целевой файл в любом случае должен находится в пределах CWD.

Почему так: необходимо добиться того, чтобы cli-harness мог быть доступен в масштабах всей системы и запускаться из CMD подобно базовым утилитам, но чтобы его рабочая директория строго задавалась CWD в ситуации, когда процесс напрямую вызван из целевой директории, либо таковая явно указана в аргументах командной строки + все конфигурационные файлы агентского цикла должны находится в целевой рабочей директории и только там (одна директория - свои собственные конфигурационные файлы).

## Output buffer for shell commands
Модифицировать команду `run_shell/request_command_shell_execution` добавив последним аргументом `output_buff_size` - числовое значение, которое задаёт количество символов, возвращаемых агенту в качестве результата выполнения команды.

Это нужно для того, чтобы дать агенту возможность контролировать объём output информации получаемой в процессе исполнения команды, чтобы не читать километры выводов в ситуации, когда для понимания смысла результата достаточно последних пары строк.

Важные моменты:
- буфер содержит определённое количество символов вывода команды с конца
- при переполнении буфера, новые значения просто вытесняют старые
- если размер буфера задан как `-1` - это значит возвращаем агенту весь лог работы команды
- возможно определять размер буфера не в количестве символов, а в количестве строк (на твоё усмотрение → опирайся на простоту реализации)

## RegExp for Deprecated-Dirs
Добавить возможность задавать запрещённые директории для fs-tool по регулярному выражению.

Например:
- `**/log`
- `**/done`
- `**/note-*`

Это нужно для того, чтобы гибко запрещать доступ в определённые папки/файлы, которые, однако, могут находиться в разных местах и на разном уровне вложенности относительно корня репозитория.

# Правила рефакторинга Python кода
1. Пиши код на идиоматичном Python (Pythonic code):
   - строго следуй стандартам PEP 8 (стиль кода) и PEP 257 (докстринги);
   - вместо сложной иерархии наследования (ООП) отдавай приоритет композиции классов и «утиной типизации» (Duck Typing);
   - используй встроенные возможности языка: списковые включения (List Comprehensions), генераторы для экономии памяти, контекстные менеджеры (`with`) и встроенные функции (`enumerate`, `zip`, `any`, `all`);
   - обязательно используй современные аннотации типов (Type Hinting) с помощью модуля `typing` или встроенных типов (для Python 3.9+) для повышения читаемости и статического анализа (`mypy`);
2. Python — интерпретируемый и динамический ЯП, поэтому избегай «магических строк», хардкода путей и хранения секретов в коде → все конфигурационные переменные выноси в файлы конфигурации (`Tools\settings.json5`):
   - дай короткие комментарии, зачем подключаются конкретные сторонние библиотеки (прямо в файле или в документации);
   - если зависимость устарела или не используется в коде — исключи её;
   - зафиксируй версии пакетов (pinning) для обеспечения воспроизводимости среды;
3. Комментирование и документирование:
   - для всех модулей (файлов) пиши Docstring в самом начале, объясняющий назначение модуля и его ключевые компоненты;
   - документируй все публичные функции, классы и методы с помощью Docstrings в едином стиле (Google Style), четко описывая аргументы (Args), возвращаемые значения (Returns) и возможные исключения (Raises);
   - следи за тем, чтобы всё публичное было прописано в списке на экспорт (`__all__` в начале модуля);
   - для для непубличных функций, классов и их методов достаточно короткого поясняющего комментария.

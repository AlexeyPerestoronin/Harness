# Результаты

## `crates/harness/src/agent_select.rs`

### Комментарий модуля
- Было: `when `agent-setting.config` is a directory`.
- Стало: `when `agent.config` is a directory`.
- Почему: ключ конфигурации давно называется `agent.config`, комментарий устарел.

### Вывод при выборе из каталога (2+ кандидатов)
- Было: нумерованный список `N) Vendor Name (file.json5)`, с выровненным только именем `Vendor Name`.
- Стало: выровненная таблица с колонками `№`, `Vendor`, `Model`, `Cost (Input/Output/Cached)`, `Limits (Tokens/RPM/TPM/RPD)`, затем пустая строка и прежний промпт `Select agent [1-N]: `.
- Почему: по номеру в списке не было видно цен и лимитов модели; таблица показывает их сразу, а имя файла убрано, чтобы не дублировать лишнее.

### Формат ячеек
- Было: в таблице не было цен/лимитов.
- Стало:
  - цены `-1` печатаются как `-1`;
  - остальные цены печатаются без экспоненты, минимум с двумя знаками после запятой, без округления более длинной дробной части (`0.003` не превращается в `0.00`);
  - три цены объединяются через ` / `;
  - четыре лимита печатаются как целые без разделителей тысяч и объединяются через ` / `.
- Почему: требование к читаемости моноширинного вывода.

### Логика выбора
- Поведение для пустого списка, ровно одного кандидата и правила ввода не менялись.
- Почему: эти сценарии не входили в задачу и уже работают.

## Проверка

- `cargo test --workspace` — прошёл: 6 юнит-тестов `agent_select` зелёные.
- Тесты проверяют: таблицу для двух кандидатов, формат цен/лимитов, отсутствие имени файла в таблице, одинаковую ширину строк таблицы, сценарии ввода (мусор/EOF/один кандидат).

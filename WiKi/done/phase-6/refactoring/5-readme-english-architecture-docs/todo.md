# Задача на рефакторинг: English-only документация и README с архитектурой, технологиями и pipeline

## Цель рефакторинга:
Актуализировать документацию в соответствии с целями Project Owner:
- оставить только английский язык;
- добавить в `README.md` информацию об архитектуре приложения, используемых технологиях и базовых pipeline работы пользователя.

## Вносимые изменения:

### Изменение №1: удаление русскоязычной документации
- **Что хотим изменить и почему это лучше:** в репозитории не должно быть пользовательской документации на русском языке.
- **Как есть сейчас:** существует `README.ru.md`, а `README.md` содержит ссылку `[Русский](README.ru.md)`.
- **Как должно быть:** файл `README.ru.md` удалён; ссылка на него из `README.md` удалена.

### Изменение №2: раздел Architecture в README.md
- **Что хотим изменить и почему это лучше:** пользователь/разработчик должен сразу видеть, из каких частей состоит система и как они взаимодействуют.
- **Как есть сейчас:** явный раздел Architecture отсутствует.
- **Как должно быть:** в `README.md` добавлен раздел `Architecture`:
  - перечень нативных крейтов и их ответственность (`logger`, `interactions`, `auth`, `harness-api`, `conf`, `tools`, `agent-loop`, `cli-harness`) и `web-harness` как отдельного WASM-крейта;
  - простая Mermaid-диаграмма `flowchart` с потоком: `cli-harness` → `conf` → `agent-loop` → vendor API; `web-harness` → HTTPS REST → `cli-harness`;
  - указание, что клиент и сервер общаются только по HTTPS REST + polling 10 секунд.

### Изменение №3: раздел Technologies в README.md
- **Что хотим изменить и почему это лучше:** явно зафиксировать используемый стек.
- **Как есть сейчас:** технологии упоминаются разрозненно.
- **Как должно быть:** в `README.md` добавлен раздел `Technologies` со списком: Rust/tokio, axum + axum-server + rustls, rcgen, async reqwest, Leptos CSR, Trunk, gloo-net, serde/serde_json, JSON5 и т.д. Кратко указано назначение каждой технологии.

### Изменение №4: раздел базовых пользовательских pipeline
- **Что хотим изменить и почему это лучше:** пользователь должен понимать основные сценарии работы.
- **Как есть сейчас:** сценарии частично описаны, но не выделены как pipeline.
- **Как должно быть:** в `README.md` добавлен раздел `User pipeline` (или `Basic workflows`) с тремя базовыми сценариями:
  1. Console session: `harness.exe --conf harness.json5 --prompt "..."` → выбор агента/ключа при необходимости → сессия → `log.md`/`dump.json`.
  2. Server + web client: `harness.exe --serve` → токен из stdout → открыть `harness.wasm` → подключиться → `POST /run` → polling `runUrl` → `pendingInput` → результат.
  3. Embedded plugin: подключение `web-harness` через Cargo/Git и опциональная фича `fs-panel`.
- Также в `README.md` добавлена ссылка на `REST-API.help.md` (если файл уже создан).
